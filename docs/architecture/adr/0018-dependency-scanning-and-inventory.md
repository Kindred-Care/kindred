# 0018. Dependency scanning, exceptions and inventory

- Status: Accepted
- Date: 2026-10-17 (risk assessment completed the same day, at the founder's request)
- Source: Section 3 required checks ("Dependency scan"), Section 9 dependencies ("known-vulnerable
  packages block release unless an ADR records the reason"); decision 103

## Decision

CI job `dependency-scan`:

1. **NuGet**: `NuGetAudit` runs on every restore with warnings as errors, and
   `dotnet list package --vulnerable --include-transitive` fails the job on any finding. Package versions
   are central (`Directory.Packages.props`) and locked (`packages.lock.json`, locked mode in CI).
2. **npm**: `scripts/dev/check-npm-audit.mjs` runs `npm audit` for `apps/mobile` and `scripts/codegen`.
   High and critical advisories fail the job unless listed in
   [`docs/security/dependency-exceptions.json`](../../security/dependency-exceptions.json) with a reason,
   this ADR and a review date. An expired exception fails the job. Moderate and low advisories are
   reported as warnings.
3. **Bundle guard**: CI job `build` exports both app bundles with source maps and
   `scripts/dev/check-bundle-deps.mjs` fails if `node-forge`, `braces`, `micromatch`, `sprintf-js` or the
   npm `uuid` package is in either bundle. Every accepted advisory below rests on "build time only", so
   that premise is enforced rather than assumed.
4. **Inventory**: CycloneDX SBOMs for the backend (`dotnet CycloneDX`) and the mobile app (`npm sbom`)
   are uploaded as a build artifact on every run.

Dependabot alerts are enabled on the repository (free) and report when a fixed version is published.
GitHub dependency review is not used on this private repository because it needs the paid Code Security
add-on. These scans supplement branch protection (ADR 0016); they do not replace it.

## Risk assessment of the npm advisories (2026-10-17)

The whole dependency tree was checked against the GitHub Advisory Database. The `expo` (58.0.14) and
`@expo/cli` (58.1.11) versions in use are the latest releases, so no Expo upgrade removes these packages.
The app bundles were exported with source maps: the Android bundle has 1,138 modules and the iOS bundle
1,145, and **neither contains any of the packages below**.

### GHSA-86w9-cpqp-85rv: node-forge 1.4.0 (high, CVSS 7.5)

- **Flaw.** RSA PKCS#1 v1.5 signature verification accepts extra elements inside the DigestAlgorithm
  sequence, so an attacker can forge a signature that verifies against a **low-exponent RSA public key**.
  Exploiting it requires node-forge to verify an attacker-supplied signature.
- **Fix available?** No. Every release up to 1.4.0 (the latest, March 2026) is affected and the advisory
  lists no patched version. Upstream (`digitalbazaar/forge`) has five open, unmerged community pull
  requests (#1152, #1157 to #1160) and no maintainer release.
- **How Kindred reaches it.** Only through the Expo CLI on a developer machine or build server:
  `@expo/code-signing-certificates` (development signing of `expo-updates` manifests: it signs with the
  developer's own generated key and then verifies that same signature) and the iOS code-signing helper
  used by `expo run:ios` (reads the developer's own Apple certificate). Neither path verifies a signature
  supplied by another party, and keys generated by node-forge use exponent 65537. Kindred does not use
  `expo-updates` in Milestone 1.
- **Not in the app.** Confirmed absent from both bundles; the bundle guard keeps it that way.
- **Residual risk: low.** No path processes untrusted signatures. The risk would rise if Kindred later
  verified third-party signatures with node-forge (for example, `expo-updates` code signing in production
  using its verification on devices); that design must re-run this assessment first.
- **Remediation options considered.** (a) Upgrade: none exists. (b) npm override to another
  library: not possible, Expo calls node-forge's API directly. (c) Patching node-forge locally from an
  unmerged pull request: rejected, because it means maintaining an unreviewed change to cryptographic code
  to protect paths that never see untrusted input. **Decision: accept temporarily**, re-evaluate as soon
  as a fixed node-forge or an Expo release without it is published (Dependabot alert), and in any case by
  2027-01-15.

### GHSA-vfj7-8cjw-p6xm: braces 3.0.3 (high, CVSS 7.5)

- **Flaw.** Deeply nested brace patterns exhaust the call stack and crash the Node.js process (denial
  of service). Exploiting it requires an attacker to supply a glob pattern.
- **Fix available?** No. 3.0.3 (May 2024) is the latest release and is in range. Upstream
  (`micromatch/braces`) has five open, unmerged community fixes (#78, #79, #82, #87, #88).
- **How Kindred reaches it.** `micromatch` inside Metro's file map (watching and filtering project
  files) and inside Jest. The patterns come from the Expo, Metro and Jest configuration in this
  repository, never from users or network input.
- **Not in the app.** Confirmed absent from both bundles; the API (.NET) does not use it.
- **Residual risk: very low.** The worst case is that a malicious pull request adds a pathological
  pattern to a config file and crashes the bundler in CI, which is visible, harmless to data, and stopped
  by review and the required checks.
- **Decision: accept temporarily**, with the same re-evaluation triggers (Dependabot alert, Expo release)
  and review date 2027-01-15.

### GHSA-w5hq-g745-h8pq: uuid 7.0.3 (moderate) — remediated

- `v3()`, `v5()` and `v6()` can write out of bounds into a caller-supplied buffer. Fixed in 11.1.1.
- Reached through `@expo/config-plugins` → `xcode` during iOS prebuild. `xcode` only calls `uuid.v4()`
  with no buffer, so it was never affected.
- **Remediated anyway:** `apps/mobile/package.json` overrides `xcode`'s `uuid` to `^11.1.1`. Verified that
  the dependency resolves to 11.1.1 and that `v4()` returns valid IDs through the same import path
  `xcode` uses. The full iOS prebuild runs on macOS during the simulator check (it is skipped on Windows).

### GHSA-hp3w-g68c-fv3c: sprintf-js 1.0.3 (moderate, CVSS 5.3)

- Unbounded precision specifiers throw and abort the call. No patched version exists.
- Reached only through `js-yaml` 3 → `argparse` inside `babel-plugin-istanbul`'s config loader, used by
  Jest coverage on this repository's own configuration. Not in the app or the API.
- **Residual risk: negligible.** Reported as a warning; not an exception entry because it is below the
  blocking threshold.

## Exceptions currently accepted

See [`dependency-exceptions.json`](../../security/dependency-exceptions.json): `node-forge` and `braces`,
each with the reasoning above. An exception is removed as soon as a fixed version can be installed.
